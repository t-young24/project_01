# 세라젬 웰라운지 고객 셀프 문진 — 기능 명세

세라젬 웰라운지 매장의 태블릿 또는 고객 본인의 휴대폰에서, 대기 중인 고객이 스스로 불편한 부위를 입력하고
체험존을 고른 뒤, 결과를 매니저에게 전달하고 체험 후 건강 체크 결과를 확인하는 화면 프로토타입입니다.

- 대상: 60대 이상 고령층 비중이 높은 고객
- 기준 화면: 가로 1280 × 800 (태블릿). **900px 이하(휴대폰 세로)** 에서는 `css/style.css` 맨 아래 `@media` 블록으로 1단 레이아웃·작은 글자로 자동 전환
- 설계 원칙: **글자 크게 · 버튼 크게 · 한 화면에 할 일 하나 · 뒤로가기 항상 노출**

## 1. 폴더 구조

```
세라잼/
├─ index.html              화면 구조 (HTML)
├─ css/
│   └─ style.css           전체 스타일
├─ js/
│   ├─ config.js           문구 · 체험존 · 제품 · 설정값 (코드 몰라도 수정 가능)
│   ├─ handoff.js          ★ 문진 결과를 매니저 대시보드로 전달 (Firebase 설정 포함)
│   └─ app.js              동작 로직
├─ data/
│   └─ measurements.json   세라체크존 측정 결과 (측정기기가 갱신하는 파일)
├─ manager/                ★ 매니저용 응대카드 대시보드 (별도 화면)
│   ├─ index.html
│   ├─ css/manager.css
│   └─ js/data.js          mock 고객 데이터 · 근무 현황 (?mock=0 이면 숨김)
│      js/live.js          ★ 실시간 대기열 수신 (Firebase 설정 포함)
│      js/manager.js       동작 로직
├─ promo/index.html        ★ 웹 모션 홍보영상 (실제 화면 자동 시연 · 나레이션 · 자막)
├─ docs/홍보영상_대본.md    홍보영상 대본 · 스토리보드
├─ bgm.mp3                 홍보영상 배경음악
├─ 실행.bat                 로컬 서버 실행 + 브라우저 열기
└─ README.md               이 문서
```

- 고객용 화면: `http://localhost:8000/`
- 매니저용 화면: `http://localhost:8000/manager/`
- 홍보영상: `http://localhost:8000/promo/` (아래 7절)

| 바꾸고 싶은 것 | 파일 |
|---|---|
| 환영 멘트, 매니저 미연결 시 자동 배정 시간, 최대 부위 수 | `js/config.js` 상단 |
| 시연용 예약 정보 (전화번호 → 체크한 부위) | `js/config.js` → `RESERVATIONS` |
| 고객 ↔ 매니저 연동 Firebase 설정 | `js/handoff.js` · `manager/js/live.js` 의 `FIREBASE_CONFIG` (두 파일 동일하게) |
| 체험존 이름 · 설명 · 비치 제품 목록 | `js/config.js` → `ZONES` |
| 부위별 추천 가중치 | `js/config.js` → `PART_WEIGHT` |
| 리모컨 버튼 설명 | `js/config.js` → `REMOTE_GUIDE` |
| 측정 데이터 주소 / 예시 데이터 | `js/config.js` 하단 |
| 색상 · 글자 크기 · 버튼 크기 | `css/style.css` (`:root` 변수) |
| 화면 문구, 인체모형 · 리모컨 SVG | `index.html` |
| 화면 전환, 선택 로직, 정상/주의/위험 판정 기준 | `js/app.js` |

## 2. 실행 방법

### PC에서 확인
`실행.bat` 더블클릭 → 로컬 서버가 켜지고 브라우저가 `http://localhost:8000` 으로 열립니다.
(`F11` 전체화면으로 보면 실제 단말 느낌에 가깝습니다.)

> 파일을 직접 더블클릭(`file://`)해서 열면 화면은 나오지만, 측정 데이터 `fetch`가 브라우저 정책으로
> 차단되어 6단계가 "예시 데이터"로 표시됩니다. 반드시 서버를 통해 여세요.

### 태블릿 · 휴대폰에서 확인
PC와 같은 와이파이에서 `실행.bat` 실행 후, 태블릿이나 휴대폰 브라우저에서 `http://<PC IP>:8000` 접속
(PC IP는 `ipconfig` 로 확인)

### 매장 키오스크 모드
```
chrome.exe --kiosk "http://localhost:8000"
```

### 음성 안내 주의
Chrome은 사용자가 화면을 한 번 터치하기 전까지 음성 재생을 막습니다.
첫 화면에서 음성이 안 나오면 화면을 한 번 터치하면 안내가 시작됩니다.

## 3. 전체 흐름 (8단계)

```
1 시작 → 2 방문 유형(예약/일반) → 3 전화번호 → 4 부위 선택 → 5 체험존 추천 → 6 매니저 전달 확인 → 7 리모컨 안내 → 8 결과 리포트
                                              ↑ 예약 고객은 건너뜀 (예약 시 체크한 부위 사용)
```

상단 바(모든 화면 공통)
- `◀ 이전` — 큰 뒤로가기 버튼 (1단계에서는 비활성)
- 1 ~ 8 단계 표시 (현재 단계 파란색, 지난 단계 연파랑)
- `🔊` 음성 안내 켜기/끄기
- `⌂ 처음으로` — 모든 상태 초기화 후 1단계로

---

### 1단계 — 시작 화면
- 진입과 동시에 환영 음성 안내 재생 (`WELCOME_TEXT`)
- 화면 문구: "불편하신 부분을 선택해주세요"
- 자동 전환 없음 — `시작하기 ▶` 버튼을 눌러야 2단계로 (음성이 끝나면 "준비되시면 시작하기 버튼을 눌러 주세요" 안내)

### 2단계 — 방문 유형 선택
- `📅 예약 고객` / `🚶 일반 방문` 두 개의 큰 카드 중 하나를 터치 → 자동으로 3단계로 이동
- 예약 고객: 3단계 전화번호로 예약 정보를 조회해 **예약 때 체크한 불편 부위**를 불러오고 **4단계를 건너뛰어 바로 5단계 추천**으로
- 예약 정보를 못 찾으면(번호 불일치) 안내 후 일반 방문처럼 4단계로 진행

### 3단계 — 전화번호 입력 (데이터 수집용)
- 큰 숫자 키패드(0~9 · ⌫ 지움 · 전체 지움)만 제공 → 숫자 외 입력 불가
- `010-1234-5678` 형식 자동 하이픈, 11자리(01X로 시작) + **개인정보 수집·이용 동의 체크** 시 `다음` 활성화
- 입력한 번호는 6단계 매니저 전달 데이터에 포함 (재방문·예약 식별 키로 사용)
- 시연용 예약 번호(`js/config.js` → `RESERVATIONS`): `010-1234-5678` (허리3·무릎2), `010-9876-5432` (어깨2·목2), `010-1111-2222` (다리3·무릎3·골반1)

### 3-1단계 — 방문 목적 (일반 방문 고객만)
- 음성: "방문 목적을 선택해 주세요"
- `제품 체험을 먼저 해보고 싶어요` → 4단계
- `구매/구독(렌탈) 상담을 받고 싶어요` → **6-1 상담 대기 화면**으로 바로 이동 (문진 종료)
- `제품 체험과 구매/구독(렌탈) 상담을 함께 받고 싶어요` → 4단계, 매니저 전달 데이터에 상담 희망 포함
- 예약 고객은 이 화면을 거치지 않음

### 4단계 — 인체모형 부위 선택
- 정면 인체모형(SVG)을 큰 구획으로만 단순화: 머리 · 목 · 어깨 · 팔 · 등 · 허리 · 골반 · 무릎 · 다리
- 좌/우, 위/아래 도형은 **각각 따로 터치·하이라이트**되지만, 라벨과 목록에는 좌우 구분 없이 통일된 이름만 표시
  (예: 왼쪽·오른쪽 다리를 모두 골라도 목록에는 "다리가 아파요" 한 줄)
- 부위 터치 → 오른쪽 패널에 강도 선택 카드
  `1단계 약함 / 2단계 보통 / 3단계 심함` (색상 초록/노랑/빨강)
- 조사 자동 처리: "등**이** 얼마나 불편하세요?", "다리**가** 얼마나 불편하세요?"
- 최대 **5개 부위**(이름 기준) 선택, 초과 시 토스트 + 음성 안내
- 선택된 도형을 다시 누르면 그 도형만 취소, 목록의 `✕`는 같은 이름 도형 모두 취소
- 선택 목록은 오른쪽에 항상 표시, `선택 완료 ▶`로 다음 단계

### 5단계 — 체험존 추천 (다중 선택)
- 상단에 추천 근거 표시: "📅 예약 시 체크하신 부위" 또는 "선택하신 부위" + 부위·강도 칩 (예약 고객은 `부위 바꾸기`로 4단계 이동 가능)
- 선택한 부위 × 강도로 점수를 계산(`PART_WEIGHT`)해 추천 순위를 매김
- **4개 존이 처음부터 모두 표시**: 위에 `가장 추천` 1개를 크게, 아래 2열에 나머지 존 (2순위는 `함께 추천` 배지)
  → 안마의자 등 추천되지 않은 존도 바로 고를 수 있음
- 체험존: **척추존 · 휴식존 · 순환존 · 뷰티존** — 각 카드에 한두 줄 설명 + "허리 · 등 불편에 도움이 돼요" 근거
- **체크박스 방식 다중 선택**, 선택한 존은 하단에 칩 목록으로 계속 표시
- `선택 완료 ▶` → 문진 결과(부위·강도·선택 존·추천 존)를 매니저에게 전달(현재 `console.log`)

### 6단계 — 매니저 전달 확인
- "선택하신 체험이 담당 매니저에게 전달되었어요" 안내 배너
- 선택한 존마다 카드: 존 이름 · 짧은 설명 · **자세한 설명** · **비치된 세라젬 제품 목록**
- 상단 배너 오른쪽에 **대기번호**(1~`TICKET_MAX`, 기본 20 사이 임의 번호) 표시
- **매니저 배정 = 매니저 화면에서 `응대 시작`을 누르는 순간**: 이 화면에 도착하면 문진이 매니저 대시보드에 전달되고, 매니저가 그 카드의 `응대 시작`을 누르면 즉시 안내창 표시
  (매니저 화면과 연결이 안 된 경우에만 `MANAGER_WAIT_MS`(기본 20초) 뒤 자동 배정)
  - 배정 **전**에 `체험 시작 ▶`를 누르면 "아직 담당 직원이 배정되지 않았어요" 안내창만 뜨고 넘어가지 않음
  - 배정 **후**에 누르면 6단계로 이동
  - "잠시 후 담당 매니저가 체험 안내를 도와드리겠습니다" + 음성
  - 접수 번호 · 선택한 체험 · 상태(매니저 호출됨 · 대기 중)
  - `네, 기다릴게요`(닫기) / `🔔 매니저 다시 호출`
  - 다른 화면으로 이동하면 타이머 취소 · 창 자동 닫힘

### 6-1 · 6-2단계 — 상담 대기 → 담당자 배정 (구매/구독 상담만 원하는 고객)
- 6-1: "담당 매니저가 곧 안내해 드릴 예정이에요 · 잠시만 기다려 주세요" + 대기번호, 상담 요청을 매니저에게 전달(콘솔)
- 매니저 화면에서 `응대 시작`을 누르면 6-2: "담당자를 배정하였습니다 · 문진에 응해주셔서 감사합니다" + `처음 화면으로` (미연결 시에만 `MANAGER_WAIT_MS` 뒤 자동)
- 상단 단계 표시는 6번 점이 켜짐

### 7단계 — 체험 중 리모컨 안내
- 상단 배너 `❓ 버튼 사용법이 궁금하면 여기를 눌러 다시 확인하세요`
- 리모컨 그림(SVG)의 7개 버튼에 번호 표시, 오른쪽에 번호 · 아이콘 · 큰 글씨 설명 매칭
  1 전원 · 2 시작/멈춤 · 3 강도 조절 · 4 온열 · 5 시간 · 6 모드 선택 · 7 매니저 호출
- 배너를 누르면 음성 설명과 함께 버튼이 순서대로 2.6초씩 강조
- `체험 끝 · 결과 보기 ▶` → 8단계

### 8단계 — 세라체크존 결과 리포트 (체험 종료 후)
- 측정 데이터를 `MEASURE_API_URL`에서 **실제 `fetch`로 불러옴** (기본: `data/measurements.json`)
  - 성공: 하단에 측정 시각 표시
  - 실패(파일 없음 · 서버 꺼짐 · `file://`): 예시 데이터로 대체하고 **"⚠ 측정기기와 연결되지 않아 예시 데이터를 보여드리고 있어요"** 명시
- 항목: 혈압 · 맥박 · 스트레스 · 체지방 · 근육량 · 체온 (6개)
- **간단 설명(항상 표시)**: 3열 카드 — 값 · 초록/노랑/빨강 게이지 · `정상/주의/위험` 칩 · 한 줄 쉬운 설명
- **자세히 보기(버튼을 눌러야 펼침)**: 항목별 아코디언 —
  이번 측정값 · 정상 범위 · 내 위치(구간 바) · 이렇게 관리해보세요(관리 팁)
- 문구는 모두 "체험을 마치고 집에 가기 전" 상황에 맞춤 (예: "나가실 때 겉옷을 챙기세요")
- 하단 왼쪽 `📱 결과표 가져가기` → QR 창
  - QR 모양 패턴(프로토타입용 가짜) + 결과표 번호(`MMDD-0000`)
  - `확인했어요`로 닫기
- 하단 오른쪽 `처음 화면으로 ⌂` → 상태 초기화 후 1단계

## 4. 데이터 · 연동 지점

### 세라체크존 측정 데이터 (`data/measurements.json`)
```json
{
  "measuredAt": "2026-09-11T14:32:00+09:00",
  "bloodPressure": { "sys": 124, "dia": 79 },
  "pulse": 68,
  "stress": 42,
  "bodyFat": 26.3,
  "muscle": 27.1,
  "bodyTemp": 36.5
}
```
- 측정기기 PC가 이 파일을 덮어쓰면 화면에 바로 반영 (캐시 방지 처리됨)
- 기기 서버가 따로 있으면 `config.js`의 `MEASURE_API_URL` 변경, 또는 주소 뒤에 `?api=http://...` 지정
- 필수 항목이 숫자가 아니면 형식 오류로 처리되어 예시 데이터로 대체

### 판정 기준 (`app.js` → `interpret()`)
| 항목 | 정상 | 주의 | 위험 |
|---|---|---|---|
| 혈압 (수축/이완) | < 130 / < 85 | ≥ 130 또는 ≥ 85 | ≥ 140 또는 ≥ 90 |
| 맥박 (회/분) | 55 ~ 90 | 50 ~ 54, 91 ~ 100 | < 50, > 100 |
| 스트레스 (점) | < 50 | 50 ~ 74 | ≥ 75 |
| 체지방 (%) | < 28 | 28 ~ 34.9 | ≥ 35 |
| 근육량 (kg) | ≥ 24 | 20 ~ 23.9 | < 20 |
| 체온 (°C) | 35.5 ~ 37.2 | 37.3 ~ 37.7 | < 35.5, ≥ 37.8 |

> 프로토타입용 기준값입니다. 실제 적용 시 의료 자문을 거쳐 조정이 필요합니다.

### 고객 문진 → 매니저 대시보드 실시간 연동 (Firebase Realtime Database)
GitHub Pages 처럼 서버가 없는 곳에 배포해도 동작하도록, 두 화면이 Firebase Realtime Database 하나를 같이 봅니다.

```
고객 화면 (js/handoff.js) ──문진 저장──▶ Firebase RTDB ◀──실시간 구독── 매니저 화면 (manager/js/live.js)
```
- 5단계 `선택 완료` / 3-1단계 상담 선택 시 `sendHandoff()` → DB `queue/` 에 저장, **대기번호는 DB 카운터로 발급**(날짜별 1번부터)
- 매니저 화면은 `queue/` 를 구독해 새 문진이 오면 바로 카드 슬라이드인 + 알림. 상단에 `● 실시간 연결됨` 표시
- 매니저가 `응대 시작` 을 누르면 고객 화면에 **즉시 "담당 매니저가 배정되었어요" 안내창** (연결됐을 땐 시간 경과로 배정되지 않음)
- 첫방문/재방문은 `visits/{전화번호}` 기록으로 판별, 이전 방문 존·상담 결과가 응대카드 3번 칸에 표시
- 응대카드의 AI 니즈 한 줄 · Sales Script 는 부위·강도·선택 존·추천 존만으로 규칙 생성 (`manager.js` → `buildNeed` / `buildScript`)
- Firebase 연결이 안 되면 고객 화면은 기존처럼 콘솔 출력 + 임의 대기번호로 동작, 매니저 화면은 `○ 연결 안 됨` 표시
- 시연용 mock 고객(6명 + 시뮬 버튼 2명)은 기본으로 함께 표시. 실시간 문진만 보려면 `manager/?mock=0`
- DB 구조: `queue/{key}` (status: waiting → serving → done) · `counter/{YYYYMMDD}` · `visits/{전화번호}`

> ⚠ 현재 DB 보안 규칙은 **테스트 모드**(누구나 읽기·쓰기, 생성 30일 후 자동 잠김)입니다. 실제 매장 적용 전에
> Firebase 콘솔 → Realtime Database → 규칙 에서 인증 기반으로 잠가야 합니다. 전화번호는 DB 에 전체 저장되고 매니저 화면에는 뒷자리만 표시됩니다.

### 아직 연결되지 않은 부분 (현재는 `console.log`로만 기록)
| 기능 | 현재 | 연동 시 |
|---|---|---|
| 매니저 호출 / 재호출 (6단계) | 재호출 시각만 DB 에 기록(`recalledAt`) → 카드에 🔔 표시 | 호출 알림(소리·푸시) 연동 |
| 결과표 QR (8단계) | 가짜 패턴 `drawFakeQr()` | 서버에 결과 저장 → URL을 QR 라이브러리(예: qrcode.js)로 생성 |
| 세라체크존 측정 데이터 | JSON 파일 `fetch` (연동 구조 완성) | 기기 소프트웨어가 JSON을 쓰거나 HTTP로 내보내기만 하면 됨 |
| 예약 정보 조회 (3단계) | `config.js` 의 `RESERVATIONS` mock | 예약 시스템 API 로 전화번호 조회 (`findReservation`) |
| 음성 인식 (STT) | 미구현 (음성 **안내** TTS만 동작) | Web Speech API `SpeechRecognition` 또는 외부 STT |

## 5. 매니저용 응대카드 대시보드 (`manager/`)

고객이 문진 화면에서 입력한 니즈가 AI로 구조화되어 매니저 화면에 "응대카드"로 실시간 전달되는 화면.
매니저는 바쁘게 일하며 힐끗 보고 판단하므로 **정보 밀도는 높게, 우선순위는 색으로 즉시 구분**.

### 데이터 분석 근거 반영
| 근거 | 화면 반영 |
|---|---|
| 니즈 파악이 오래 걸릴수록 응대 건수 -22.4%, 체험 안내 -33.8% | 구조화된 부위·강도 + AI 한 줄 니즈를 대기 카드와 상세 최상단에 배치 → "처음부터 다시 묻지 않게" |
| 워크인 고객은 니즈 파악 2.1배(18.0분 vs 8.6분), 전체의 77.6% | 모든 대기 카드에 `🚶 워크인` / `📅 예약` 배지, 상세에 "니즈파악 평균 2.1배" 표시. 워크인도 대기열에서 응대카드 생성 |

### A. 대기 고객 목록 (메인)
- 상단 요약: 대기 중 · 워크인/예약 · 최장 대기(10분 이상 빨강) · 평균 대기 · **💬 상담 희망(상담만 N명)**
- 카드: 대기번호 · 우선순위 배지 · 접수유형 · **방문 목적**(🛋️ 제품 체험 / 💬 구매·구독 상담 / 🛋️💬 체험+상담 / 📅 예약 체험) · 첫/재방문 · 휴대폰 뒷자리 · 측정 여부 · 부위+강도 · AI 니즈 한 줄 · 체험존 · 대기시간
- **상담만 원하는 고객**(고객용 3-1에서 상담 선택 → 6-1 대기)도 같은 대기열에 들어옴: 부위·존 없이 `[💬 상담만]` 표시, 존 자리에 `💬 상담석`, 완료 버튼은 `상담 완료`(체험 안내 횟수에 미포함)
- **정렬 · 보기 필터** (목록 위 툴바): 정렬 = 오래 기다린 순(기본, 우선순위) · 최신 문진 순 · 대기번호 순 / 보기 = 전체 · 💬 상담 희망 · 🔁 재방문 · 🚶 워크인 · 📅 예약 · 응대 중 (각 칩에 인원 수 표시). 응대 중 고객은 항상 맨 아래
- **우선순위(기본 정렬)**: 대기시간 기준 — 10분 이상(빨강 우선, 상단) → 5분 이상(노랑 주의) → 그 외(초록 여유)
  (방문 인원은 문진으로 알 수 없으므로 인원 기준 우선순위는 사용하지 않음)
- 카드 터치 → B 상세
- 고객 화면에서 문진이 완료되면 **실시간으로** 새 카드가 슬라이드인 (Firebase 연동, 4절 참고)
- `＋ 새 문진 도착 (시뮬)` 버튼 또는 25초 후 자동으로 시연용 고객 추가 (`?mock=0` 이면 mock 없이 실시간 문진만)

### B. 응대카드 상세 (스크롤 없이 한 화면)
1. 기본 정보 — 휴대폰(뒷자리) · 방문유형 · 접수유형 · **방문 목적**
2. 니즈 구조화 — 부위+강도 칩, AI 한 줄 니즈(응대 행동으로 연결되는 문장)
3. 실사용자 · 이전 방문 기록 — 재방문이면 이전 방문일 · 이전에 쓴 존 · 이전 세라체크 결과(정상/주의/위험 칩) · 지난 상담 결과, 첫방문이면 '기록 없음' 안내
4. 선택 체험존 + 비치 제품 — 문진이 추천한 존과 고객 선택이 다르면 표시 (예: "척추존은 고르지 않음")
5. 세라체크존 측정 — 혈압·스트레스·체지방·근육량 게이지 (없으면 "측정 전"), 재방문이면 지난 방문 대비 변화 한 줄
6. AI Sales Script — 3줄 이내 상담 포인트 + **"효능 단정 표현 금지"** 안내 고정 표시
- `응대 시작` → 카드가 "응대 중"으로 바뀌고 목록 하단으로 / `체험 안내 완료` → 목록에서 제거, 근무 현황 수치 증가

### C. 근무 현황 (별도 탭)
- 응대 건수 · 체험 안내 횟수 · 니즈파악 평균 소요시간 — 전월 일평균 대비 증감 화살표 (초록=개선, 빨강=악화)
- 하단에 매니저 응대 팁 2줄 (`manager/js/data.js` → `INSIGHTS`)

### 표시 정보의 출처 (문진에서 수집되는 것만 사용)
| 정보 | 출처 |
|---|---|
| 워크인/예약 | 고객용 2단계 방문 유형 선택 |
| 방문 목적 (체험 / 상담 / 체험+상담) | 고객용 3-1단계 (일반 방문만, 예약 고객은 "예약 체험") |
| 휴대폰, 첫방문/재방문, 이전 방문 기록 | 고객용 3단계 전화번호 → 예약 명단·방문 기록 조회 |
| 부위 + 강도 | 고객용 4단계 (예약 고객은 예약 시 체크한 부위) |
| 선택 존 · 문진 추천 존 | 고객용 5단계 |
| 세라체크 측정값 | 체험 후 측정 (data/measurements.json) |
| AI 니즈 한 줄 · Sales Script | 위 데이터만으로 생성 — 직업·동반자·나이·통증 기간 등 문진에 없는 정보는 사용하지 않음 |

### mock 데이터 (`manager/js/data.js`)
- 대기 고객 6명 + 시뮬레이션 도착 2명: 워크인/예약, 첫방문/재방문(이전 측정 있음/없음), 측정 완료/전 케이스 혼합
- 모든 문구는 효능 단정 표현 없이 작성 ("도움이 될 수 있음", "체험 후 느낌 여쭤보기")

## 6. 홍보영상 (`promo/`)

`docs/홍보영상_대본.md` 의 60초 구성을 그대로 재생하는 웹 페이지. 고객용·매니저용 **실제 화면을 iframe 으로 띄워 자동 조작**하므로
반드시 서버를 통해 열어야 함 (`실행.bat` → `http://localhost:8000/promo/`, 또는 GitHub Pages 의 `/promo/`).

- 시작 화면에서 나레이션(브라우저 한국어 음성) · 배경음악(`bgm.mp3`) · 실제 Firebase 연동 여부 선택 → `▶ 재생`. 글꼴은 Pretendard(CDN), 오프라인이면 시스템 글꼴
- 조작: `Space` 시작 · `←` `→` 장면 이동 · `R` 처음부터 · `F` 전체화면
- **PC / 모바일 자동 전환**: 가로 화면이면 1280×720 무대, 세로 화면(휴대폰)이면 720×1280 무대로 고객·매니저 화면을 위아래로 쌓아 보여줌. 시작 화면 링크나 `?layout=mobile` / `?layout=pc` 로 강제 가능
- 주소 옵션: `?autostart=1` 바로 재생 · `?voice=0` 음성 끔 · `?bgm=0` 음악 끔 · `?live=1` 실제 Firebase 사용 · `?layout=mobile|pc`
- **MP4 로 만들기**: `F` 전체화면 → `Win + Alt + R` (Xbox Game Bar 녹화) → `▶ 시작` → 끝나면 `Win + Alt + R` 로 종료.
  녹화 파일은 `내 PC > 동영상 > 캡처` 폴더. Game Bar 설정에서 "게임 오디오 녹음"이 켜져 있어야 나레이션·음악이 들어감
- 기본(연동 OFF)은 매니저 화면에 시연용 카드가 도착하는 것처럼 보이게 처리 → DB 에 기록 남지 않음. `?live=1` 이면 실제로 Firebase 를 거침
- 장면 구성·문구 수정: `promo/index.html` 의 `SCENES` 배열 (자막 `sub`, 나레이션 `narr`, 최소 길이 `min`)

## 7. 기술 사항
- 순수 HTML / CSS / JavaScript. 외부 라이브러리는 고객 ↔ 매니저 연동용 Firebase SDK(CDN, compat 빌드)만 사용

- 로컬 서버: Python 내장 `http.server` (별도 설치 불필요, Python만 있으면 됨)
